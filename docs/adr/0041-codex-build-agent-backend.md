# Codex Build Agent Backend

Codex Build is the third built-in Agent Backend, with stable ID `codex`, delivered as a `packages/codex` adapter on the shared `@ready-for-agent/agent-backend` contract (ADR 0031), following the Grok adapter's shape. Turns run as `codex exec --json`; the Session ID is the Codex `thread_id`, captured from the early `thread.started` stream event and continued across turns and Harness restarts with `codex exec resume <thread_id>`. The `/review` Agent Command is prompt-prefixed, as in the Grok adapter. Authentication is ambient (ChatGPT OAuth or a stored API key via `codex login`, or a user-level custom `model_provider` such as Azure), with ambient `gh` for Agent GitHub Access and no Keymaxxer integration. `OPENAI_API_KEY` is inherited by Agent Turns but does not make `codex login status` report logged in.

The adapter decisions, including the Session Telemetry amendment after v1, are:

- **Provider-aware readiness inspection.** Inspection still starts with binary presence plus `codex login status`. Stored ChatGPT OAuth or API-key login remains Ready and returns the static catalog. When status is `Not logged in`, the adapter reads the user-level Codex config (`CODEX_HOME` or `~/.codex/config.toml`) and, if it selects a valid non-first-party custom provider, runs local `codex debug models --bundled` instead of treating the backend as Unavailable. `--bundled` dumps the CLI's shipped catalog without a provider auth refresh; unbundled `codex debug models` would run a command-backed token helper and `GET {base_url}/models` on a cache-less `CODEX_HOME`. Success is Ready with the adapter-bundled static catalog and an `InspectResult` warning that the provider's credentials will be validated on the first Agent Turn. Inspection never executes a configured `[model_providers.<id>.auth]` token command and never probes with `codex exec` (the former is owned by Codex on the first Agent Turn; the latter would make a billable model request). Default OpenAI, other built-in providers, missing config, malformed custom-provider config, and a failing `codex debug models --bundled` stay Unavailable with actionable copy — not an `OPENAI_API_KEY` hint, because `codex login status` disables environment-key lookup.
- **Static model catalog.** The Codex CLI has no one-shot models command (open feature request: openai/codex#23279), so the "instance-wide Agent Model catalog through atomic readiness inspection" requirement of ADR 0031 is met with an adapter-bundled static catalog rather than a CLI-reported one. The catalog lists only current-generation models — gpt-5.5 and up — with each model's reasoning efforts as Thinking Levels; legacy models are excluded even when an operator's account can still access them. Adding a newly released OpenAI model requires a Harness release. Supporting arbitrary third-party model catalogs from custom providers is out of scope; a custom provider that is Ready still offers the adapter-bundled catalog. When openai/codex#23279 ships a supported non-interactive models command, the catalog source migrates to CLI-reported with no adapter contract change. The Codex App Server's `model/list` JSON-RPC method was rejected: it would introduce a long-lived server process into readiness inspection, breaking the atomic inspection shape.
- **Unsandboxed turns.** Turns run with `--sandbox danger-full-access` because Codex's OS-level sandbox defaults (read-only, and network-blocked under `workspace-write`) would break shell, git, and `gh` work mid-turn in ways that surface as confusing Step Run failures. This is parity with the OpenCode and Grok adapters, which run unsandboxed; containment remains the git worktree plus operator trust in the backend.
- **Codex-owned Session Telemetry.** Issue #911 supersedes the v1 decision to omit this optional capability (ADR 0033). Codex Build live-reads the Codex-owned rollout under `CODEX_HOME` for the captured Session ID, preferring the optional threads index for location and timestamps and falling back to the date-partitioned sessions tree. The last cumulative `token_count.info.total_token_usage` supplies token totals; the Harness does not persist telemetry or invent USD cost.

## Consequences

New OpenAI models are unavailable to operators until a Harness release updates the static catalog, and an OpenAI-side model deprecation surfaces as an ordinary Step Run failure until the operator selects a newer model. A custom provider that inspects Ready can still fail on the first Agent Turn if Codex's token command or the provider rejects credentials. The static catalog and sandbox stance should be revisited if OpenAI ships a one-shot models command or if the Harness later adopts a general backend-sandboxing story.
