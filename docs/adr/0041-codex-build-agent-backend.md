# Codex Build Agent Backend

Codex Build is the third built-in Agent Backend, with stable ID `codex`, delivered as a `packages/codex` adapter on the shared `@ready-for-agent/agent-backend` contract (ADR 0031), following the Grok adapter's shape. Turns run as `codex exec --json`; the Session ID is the Codex `thread_id`, captured from the early `thread.started` stream event and continued across turns and Harness restarts with `codex exec resume <thread_id>`. The `/review` Agent Command is prompt-prefixed, as in the Grok adapter. Authentication is ambient (ChatGPT OAuth or a stored API key via `codex login`, or a user-level custom `model_provider` such as Azure), with ambient `gh` for Agent GitHub Access and no Keymaxxer integration. `OPENAI_API_KEY` is inherited by Agent Turns but does not make `codex login status` report logged in.

The adapter decisions, including the Session Telemetry amendment after v1, are:

- **Provider-aware readiness inspection.** Inspection still starts with binary presence plus `codex login status`. Stored ChatGPT OAuth or API-key login remains Ready only after a bounded first-party catalogue discovery (below). When status is `Not logged in`, the adapter reads the user-level Codex config (`CODEX_HOME` or `~/.codex/config.toml`) and, if it selects a valid non-first-party custom provider, runs local `codex debug models --bundled` instead of treating the backend as Unavailable. `--bundled` dumps the CLI's shipped catalog without a provider auth refresh; unbundled `codex debug models` would run a command-backed token helper and `GET {base_url}/models` on a cache-less `CODEX_HOME`. Success is Ready with the **picker-visible bundled** models (not an adapter-owned allowlist, and not arbitrary custom-provider deployment IDs) and an `InspectResult` warning that the provider's credentials will be validated on the first Agent Turn. Inspection never executes a configured `[model_providers.<id>.auth]` token command and never probes with `codex exec` (the former is owned by Codex on the first Agent Turn; the latter would make a billable model request). Default OpenAI, other built-in providers, missing config, malformed custom-provider config, a failing or unusable `--bundled` dump, and first-party discovery failure stay Unavailable with actionable copy — not an `OPENAI_API_KEY` hint, because `codex login status` disables environment-key lookup. Empty Ready catalogues are rejected: they would skip ordinary admission gating.
- **Discovered model catalog (issue #1260).** First-party inspect opens a short-lived `codex app-server --listen stdio://`, sends `initialize` / `initialized`, then paginates `model/list` with `includeHidden: false`. The child is always terminated; there is no persistent app-server, no `thread/start`, no `turn/start`, and no inference. Wire format is newline-delimited JSON without a `jsonrpc` member. Executable Agent Model ids are the advertised `model` strings; Thinking Levels are `supportedReasoningEfforts[].reasoningEffort` as open tokens (including `max` / `ultra` when Codex returns them). Hidden entries stay hidden. Codex CLI 0.153.4 is the supported baseline for reliable bundled Astra visibility; unsupported CLIs, timeouts, malformed pages, repeated cursors, and empty usable catalogues fail inspect with upgrade/Recheck copy. Recheck Agent Backend refreshes the Harness snapshot through the same inspect path — Codex itself may still serve cached metadata (`model/list` has no forceRefresh). Saved model selections are never rewritten because Codex marks a new default. The earlier rejection of app-server `model/list` applied to a long-lived server; a bounded stdio session preserves atomic inspection.
- **Unsandboxed turns.** Turns run with `--sandbox danger-full-access` because Codex's OS-level sandbox defaults (read-only, and network-blocked under `workspace-write`) would break shell, git, and `gh` work mid-turn in ways that surface as confusing Step Run failures. This is parity with the OpenCode and Grok adapters, which run unsandboxed; containment remains the git worktree plus operator trust in the backend.
- **Codex-owned Session Telemetry.** Issue #911 supersedes the v1 decision to omit this optional capability (ADR 0033). Codex Build live-reads the Codex-owned rollout under `CODEX_HOME` for the captured Session ID, preferring the optional threads index for location and timestamps and falling back to the date-partitioned sessions tree. The last cumulative `token_count.info.total_token_usage` supplies token totals; the Harness does not persist telemetry or invent USD cost.

## Consequences

Newly advertised Codex models appear after Recheck (or the next inspect) without a Harness release, including GPT-6 Astra when the installed CLI lists it. A model or effort that leaves the discovered catalog is preserved as unavailable rather than rewritten. A custom provider that inspects Ready still offers only bundled picker-visible models and can still fail on the first Agent Turn if Codex's token command or the provider rejects credentials. Discovery failure makes Codex Build Unavailable rather than offering a stale hardcoded list. The sandbox stance is unchanged.
