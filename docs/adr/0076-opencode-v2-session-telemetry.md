# OpenCode Session Telemetry uses the V2 API

Supersedes the OpenCode SQLite sentence in [ADR 0033](0033-backend-scoped-optional-session-telemetry.md) for Session Telemetry, Agent Turn Tail, and startup-activity detection.

OpenCode 2 no longer supports `opencode db path`. Session Telemetry, Agent Turn Tail, and startup-activity detection read the experimental V2 HTTP API through `@opencode/client` 2.x. They use the same server as agent execution: the harness-owned OpenCode server when Keymaxxer is enabled ([ADR 0078](0078-harness-owned-opencode-server.md)), otherwise local service discovery and authentication (`Service.discover` plus `Service.headers`) or the same configured explicit server. Reads do not start the shared service and do not launch Agent Turns. A failed owned server is reported as unavailable and is not replaced by shared-service discovery. There is no V1 database fallback and no hardcoded database path.

Accounting uses `GET /api/session/{sessionID}` `Session.Info`: model, variant as Thinking Level, token rollup (input, output, reasoning, cache read/write), cost, and created/updated timestamps. That rollup matches the V2 session record. Summing currently listed assistant messages under-counts compacted history, so message totals are not used. Child sessions stay out of the parent total, matching the previous session-row read. Agent Turn Tail walks bounded newest-first message pages until the latest user message, keeps assistant text and tool name/status, and drops tool payloads and child-session transcripts. Startup activity is a child session or a parent `task`/`subtask` part created at or after the turn spawn. Probe errors do not disarm the startup window; the existing timeout still applies.

A missing session is `MISSING`. Transport failures, including a server that is not yet reachable during startup, are transient `UNAVAILABLE` and Retry can recover. Failure to discover or reach a server is not a compatibility failure. Authentication failures and a response that does not match the session data the harness reads are persistent `UNAVAILABLE` with an actionable diagnostic that is not described only as a transient retry. A server version string is not a runtime compatibility gate and is not probed before telemetry reads. Diagnostics do not include credentials, transcript contents, or a migration note that there is no V1 fallback.

The HTTP API is experimental and is read through `@opencode/client` 2.x. Runtime connection does not accept or reject a server from its version string. Build-time contract checks still fail when an installed OpenCode cannot confirm the operations this package reads, instead of treating a failed lookup as success.

Session-model reassertion still writes the on-disk session record. That write path is outside this decision.
