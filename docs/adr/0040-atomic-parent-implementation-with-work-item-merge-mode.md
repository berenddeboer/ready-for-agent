# Atomically implement Parent Issue children with Work Item merge mode

`Implement all with auto-merge` is one atomic command over the Parent Issue's currently open children, not a parent-level Work Item or durable batch. It creates ordinary Work Items for children without unfinished work, updates existing unfinished child Work Items, and pins each covered Work Item's Work Item Merge Policy to `always`; atomic enrollment prevents the UI from claiming the parent was queued when only some children were accepted.

`Always` skips Classify independently of the live Repository Merge Policy, but preserves pending, failed, and Expected checks, conflict handling, merge revalidation, and Forge requirements. After the Check-Start Deadline, `no_checks` is green for Always and not for Classify (ADR 0059). Child Work Items otherwise remain independent: blockers use Queue, unblocked children use normal admission, siblings may run concurrently, and one child's later failure does not stop another. This keeps the feature a bulk operator convenience and leaves room for Implement With to pin the same Always without introducing a second lifecycle.
