# Dialogs use browser-addressable overlay routes

Harness Settings, Repository settings, and Session Telemetry remain modal dialogs but gain stable URLs: `/settings`, `/repos/<repository-id>/settings`, and `/session/<work-item-id>/telemetry`. Explicitly opening a dialog pushes a history entry, so Back closes it, Forward reopens it, and Save, Cancel, Escape, or Close returns to the exact originating location; direct navigation renders the same dialog over its canonical background and closes to `/`, `/repos`, or `/` respectively. In-app Settings retains the runtime surface via mask; direct/refresh still use Pipeline. Automatic first-run Harness Settings remains local-only and does not change history, and it is suppressed while a different routed dialog is requested.

Repository routes use the stable Repository ID rather than Project Path because Project Path is ambiguous without Forge and Forge Host and may contain nested GitLab groups. The telemetry route deliberately uses a Work Item ID even though its first segment is `session`: Session Telemetry is retrieved through the owning Work Item, while a backend-local Session ID is opaque and may not exist. Routed dialogs preserve existing search parameters and interaction behavior; abandoned drafts are discarded, navigation is blocked while Save is pending, missing resources render an in-dialog not-found state, and optional Session Telemetry retains its distinct unavailable, unsupported, loading, and failure states.
