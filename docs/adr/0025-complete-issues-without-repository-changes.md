# Complete Issues Without Repository Changes

Ready For Agent supports agent-executable Issues whose objective produces findings or GitHub-side work but no repository changes. After Implement, Assess Changes compares the worktree and branch with the Work Item's recorded starting commit; observable changes continue to Pre-Commit without consulting OpenCode, while an apparently unchanged result is confirmed by the Implement Session using the build model. A confirmed No-Change Outcome includes a concise summary and skips Pre-Commit and Review because repository quality gates have nothing to validate.

When a Work Item still reaches Commit with nothing to publish — no commit after the starting commit, and nothing commitable after excluding harness-owned artifacts — Commit asks the same Session the same confirmation rather than generating publication copy, native-committing, or invoking Repair Fallback. A confirmed late No-Change Outcome persists the summary and follows the same Close Issue tail. Empty git is still not itself completion: the rejected alternative remains treating an empty Commit or PR as done without asking the Session. The ask may now run at Commit as well as at Assess Changes.

The no-change branch persists the summary, posts it once to the GitHub Issue using a Work Item marker, closes the Issue with the completed reason through GitHubService, runs local cleanup, and completes the Work Item without a pull request. Close Issue is retryable and idempotent, and an already-closed Issue is accepted after ensuring the summary exists. Merge Policy does not gate this branch because there is no pull request; Implement Locally provides operator approval by pausing before Close Issue, just as changed work pauses before Commit. Rejected alternatives were requiring an operator-selected task type, treating an empty Commit or PR as completion, running repository quality gates on unchanged work, and relying only on Git without asking the Implement Session whether the absence of changes was intentional.
