# GitLab domain mapping: standalone issues, body blockers, pipeline jobs as status checks

GitLab (ADR 0042) maps onto the existing GitHub-shaped domain rather than extending it. Every open Ready-labeled GitLab issue reconciles as a **Standalone Issue** — no Parent/Child and no Implement All — because issue hierarchy and blocking links are paid-tier GitLab features that a self-managed instance such as `git.drupalcode.org` cannot be assumed to have. Listed Blockers still work: they are parsed from a `Blocked by: #n` line in the issue body, so Queue and Waiting for blockers apply to GitLab. Closing-MR ownership ports unchanged via `Closes #iid` in merge requests. A **PR Status Check on GitLab is one job of the pull request's head pipeline**: failed `allow_failure` jobs and manual or canceled jobs are never red, so Watch, Check-Start Anchors and Deadline, Status Check Handoffs, and retry operate unchanged; GitLab has no required status contexts, so a GitLab pull request never has Expected PR Status Checks. GitLab issues and merge requests come from **separate per-project number sequences**, unlike GitHub's shared space, so harness code must not treat one number as unambiguous across the two kinds. GitLab credentials resolve ambient-first — `GITLAB_TOKEN`, then `glab` CLI — with Keymaxxer per-Repository vault support (provider `gitlab`, account `<forge-host>/<project-path>`, token `GITLAB_TOKEN_<HOST>_<PATH>`) delivered as a follow-up ticket; Agent Turns use `curl` or `glab` rather than assuming `gh`.

**Considered Options.** Probing the instance for paid-tier features before deciding was rejected: it designs for capabilities most GitLab instances lack, and the body convention matches how Drupal.org issues already reference each other. Emulating hierarchy through markdown task lists was rejected: task lists on Drupal.org are checklists, not sub-issues, and the parsing would invent semantics the platform does not have. Treating the whole pipeline as one status check was rejected: it collapses every failure into one blob and loses per-job accumulation and the staggered-settle behavior Watch relies on. Requiring Keymaxxer for GitLab from day one was considered; the operator chose ambient-first credentials with the vault integration as a separate ticket.
