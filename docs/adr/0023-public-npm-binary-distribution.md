# Public npm binary distribution

The Harness is distributed as a single public unscoped package `ready-for-agent` whose bin boots the full local app (UI + backend), not as a multi-package publish of every workspace library. Runtime is a **compiled Bun binary** so end users need not install Bun; a thin JS launcher plus **platform packages as `optionalDependencies`** (`ready-for-agent-linux-x64`, `ready-for-agent-darwin-arm64`, `ready-for-agent-win32-x64`, …) installs only the host binary (esbuild-style). Supported platforms: linux, darwin, and win32 × x64/arm64 (npm `os`/`cpu` fields; Node reports Windows as `win32`). Windows binaries use a `.exe` suffix in the platform package. Host tools remain external: `git`, `gh`, and OpenCode on PATH; Keymaxxer is optional via `KEYMAXXER_ENTRYPOINT` or `keymaxxer` on PATH—no hardcoded developer contrib path. Operator CLI commands (`add`, …) live on the same binary; the separate `apps/cli` product is retired. Publishable sources live under `apps/ready-for-agent` plus platform packages. Linux x64 is compiled with Bun's `bun-linux-x64-baseline` target so pre-Haswell CPUs (no AVX2/BMI2) can run the published binary. Rejected: Node-native rewrite for v1, fat multi-OS tarball, postinstall download from GitHub, dual npm packages (harness + cli), a seventh `*-baseline` optionalDependency (npm `os`/`cpu` cannot express AVX2, so both packages would install on every linux-x64 host), and add-repository as a web form instead of the binary.
