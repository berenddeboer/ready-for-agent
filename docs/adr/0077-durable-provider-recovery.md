# Resume transient provider failures with a durable episode

A classified transient provider failure schedules Provider Recovery instead of waiting for manual Retry. The completion transaction records a Provider Recovery Episode, releases the Worker Slot, acknowledges the execution job, and inserts one delayed wake job. The wake is not a Step Run and holds neither a Worker Slot nor an Agent Turn permit. A due wake validates that the episode generation and deadline are still current, re-checks the configured maximum wait, then seeks ordinary Worker Slot admission—including repository fairness and CI holds—and creates a fresh Step Run for that same Lifecycle Step only when admitted. This keeps the failed attempt immutable and lets SQLite recover the deadline across process restarts.

The episode is separate from Autonomous Retry Budget. Delays are 1, 2, 4, 8, then 15 minutes with bounded jitter, never earlier than a trustworthy provider retry deadline. After one hour the cadence is 30 minutes and an escalation indicator is persisted. The maximum elapsed wait is a nullable harness setting, unlimited by default; exceeding it stops automatic attempts and retains the Session and worktree for explicit Retry. A successful resumed turn ends the episode. A different permanent failure exits it. Pause, Interrupt, Abandon, Reset, terminal completion, and human-required outcomes cancel a pending wake. Explicit Retry supersedes an outstanding wake in the same transaction that creates the replacement Step Run, so competing schedulers cannot run two turns. The resumed Step Run uses the existing step recovery path and Session; it does not replay the workflow or substitute a model. Cross-Work-Item cooldown coordination and the settings UI are later tickets.
