# Production lifecycle uses Effect Scope inside the Promise host boundary

`startProductionLifecycle` remains a Promise-facing host API (`Promise<ProductionLifecycleHandle>` with `{ url, dispose }`) because Bun HTTP, process signals, detached browser launch, and process exit must live outside Effect. Inside that boundary, resource orchestration is no longer a hand-rolled reverse-order teardown list: migrations complete first, then a sequential Effect `Scope` owns the Keymaxxer Sidecar (when spawned), application runtime, and HTTP server via `Effect.acquireRelease`. Dispose closes the Scope once (memoized for concurrent callers); finalizers run LIFO so teardown is always reverse acquisition order, including partial startup after the Sidecar is up. Multiple finalizer failures are re-surfaced as `AggregateError` so the disposal contract stays diagnosable at the Promise edge. Owned Sidecar bootstrap uses `ChildProcessSpawner` with `Effect.timeout` and `Effect.raceFirst` (stdout bootstrap URL vs early process exit) instead of a manual `node:child_process` settled-flag state machine. Signal handlers and the child-exit watchdog stay thin Promise-side triggers that call `dispose`.
