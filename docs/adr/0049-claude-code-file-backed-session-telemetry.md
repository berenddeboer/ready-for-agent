# Claude Code Session Telemetry from transcript files

Claude Code flips Session Telemetry from unsupported (ADR 0047 v1) to supported (issue #791) via a file-backed live-read of Claude Code's own on-disk session transcripts, mirroring the Grok Build on-disk provider (ADR 0033). `getSession(sessionId)` scans `$CLAUDE_CONFIG_DIR/projects/*/<sessionId>.jsonl` (default `~/.claude`; `CLAUDE_CONFIG_DIR` resolved like the adapter's spawn environment) for the Harness-preassigned Session UUID — the same cross-project search Claude Code itself performs when resuming a session by ID — then folds `assistant` lines, summing `message.usage` (`input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`) from the main transcript plus, recursively, that session's `subagents/` transcripts, because subagent usage is recorded in separate files and not inside parent assistant lines (verified against production transcripts). The reported model is the last `assistant` line's `message.model` with its `effort` as the Thinking Level; `providerId` is `anthropic` for alias ids and `bedrock` when the model id is an inference-profile ARN. `cost` is `null` and `reasoning` is `0`: the transcript carries no cost field and no reasoning token field (thinking output is inside `output_tokens`). Timestamps are the minimum and maximum line timestamps. Availability: no matching transcript in any project directory → `MISSING`; an IO/permission failure reading a matching file, or the same session id found in two project directories → `UNAVAILABLE` rather than arbitrary attribution. Folding is tolerant: unparseable lines, unknown types, and a truncated trailing line from a live write are ignored, not errors.

Deliberate decisions that are part of this choice:

- **File-backed live-read, never harness capture.** The Harness stores no telemetry of its own; every Session Telemetry query reads the backend's durable session record. This keeps the capability consistent with the OpenCode and Grok providers and avoids a Harness-owned telemetry store.
- **Rejected alternatives.** Per-stream capture from `-p --output-format stream-json` events into a Harness store (heavyweight, Harness-owned writes, and only covers sessions that run after the feature ships); `~/.claude.json` `projects.<path>` `lastSessionId`/`lastTotal*`/`lastCost` counters (not populated for Harness Work Item worktree directories — `-p` sessions there do not register — and stale where present, with `lastSessionId` pointing at a transcript that no longer exists); token×pricing cost derivation (fragile against Anthropic price changes and wrong under Bedrock).
- **Accepting an internal format.** Anthropic's docs warn the transcript entry format is internal and changes between versions. Acceptance is deliberate: folding ignores unknown shapes instead of failing, and unit fixtures are pinned from real transcripts so a format change surfaces as a failing test, not a silent wrong number.

## Consequences

Claude session telemetry shows tokens, model, Thinking Level, and timestamps but no cost until a future cost source ships, and `reasoning` reads 0. A session with no transcript yields `MISSING`, which also covers runs made with `--no-session-persistence`, hosts with `CLAUDE_CODE_SKIP_PROMPT_HISTORY=1`, and transcripts removed by the 30-day `cleanupPeriodDays` retention. Review turns share the Work Item session transcript, so a mixed-model history resolves to the model of the last `assistant` line, and a human who resumes the same session interactively in the worktree contributes to the totals — which is correct, since it is the same Session. An operator's `CLAUDE_CONFIG_DIR` must match between turn spawns and telemetry reads; both derive from the Harness process environment, so they agree unless the operator changes it mid-Work-Item.
